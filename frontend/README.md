# Frontend

The web client of the music licensing workflow: React 19, TypeScript, Vite,
TanStack Router (file-based routes) and TanStack Query, shadcn/ui on
Tailwind CSS v4, react-hook-form with zod. The interface is in Spanish and
dark only; the design notes are in [`../docs/frontend.md`](../docs/frontend.md).

## Quick start

Needs [bun](https://bun.sh) and a running backend (`make dev` or `make up`
from the repository root).

```bash
bun install
bun run dev            # http://localhost:5173, /api proxied to http://localhost:8080
```

Sign in with a seeded user (`admin@acme.test` sees everything,
`licensing@acme.test` only movies and licenses). The one-time code is
printed in the backend log: `make logs` with Docker, or the terminal of
`cargo run`.

From the repository root the same is `make fe-install` and `make fe-dev`.
`make up` builds the production image too and serves it on the same port
through nginx (see "Production image").

## The API client

`lib/api` is the only place that knows HTTP. It is built in layers so that
adding an endpoint is a typed, two-line job:

1. **`types.ts`**: the wire types, written from the Rust structs the backend
   serialises. `Option<T>` is `T | null`, enums are string unions with a
   companion array for selects (`LICENSE_STATES`, `MOVIE_STATUSES`, …).
2. **`contracts.ts`**: one interface per domain (`MoviesApi`, `TracksApi`,
   `LicensesApi`, …) and `Api`, the object that groups them. The interface
   is what screens and queries program against; a fake that satisfies it
   works in tests.
3. **`http.ts`**: `createHttpClient({ baseUrl, renewSession })` returns
   `get/post/put/delete<T>(path, { query, body })`. It sends the cookies,
   turns the backend's error envelope into `ApiError { status, code, kind,
message, details, requestId }`, and on a 401 renews the session once and
   retries (auth endpoints opt out with `renewSession: false`).
4. **`<domain>.ts`**: `createMoviesApi(http): MoviesApi` etc. Each method is
   one call: `list: (filter) => http.get<Paginated<Movie>>("/movies", { query: { ...filter } })`.
   TypeScript checks the return type against the contract.
5. **`index.ts`**: wires `http`, `api` and `session` together and re-exports
   `ApiError`, `isApiError`, `describeError` and `fieldErrors`.
6. **`errors.ts`**: `describeError(e)` maps every error `code` to a Spanish
   title and a what-to-do line; `fieldErrors(e)` extracts the validator's
   per-field messages for forms.

`lib/queries/<domain>.ts` wraps the client for TanStack Query: `movieQueries.list(filter)`
and `movieQueries.detail(id)` are `queryOptions` (key and function in one
place), shared by route loaders (`ensureQueryData`) and components
(`useSuspenseQuery`); `useCreateMovie()`, `useTransitionLicense(track)`, …
are mutations that write the answer into the cache and invalidate what the
server may have changed.

### Adding an endpoint

1. Add the request and response types to `lib/api/types.ts`.
2. Add the method to the domain interface in `lib/api/contracts.ts`.
3. Implement it in `lib/api/<domain>.ts` (the compiler points at the gap).
4. Expose it in `lib/queries/<domain>.ts` as a `queryOptions` factory or a
   mutation hook.
5. If the backend can answer with a new error `code`, give it a text in
   `lib/api/errors.ts`.

### Adding a screen

1. Create `src/routes/_app/<path>.tsx` with `createFileRoute`; the plugin
   regenerates `routeTree.gen.ts` on `dev`/`build`.
2. Validate search params with zod (`validateSearch`) and load with
   `context.queryClient.ensureQueryData(...)` in `loader`.
3. Guard with `beforeLoad: ({ context }) => requireScope(context.me, "x:read")`
   when a scope is required; hide buttons with `useCan("x:write")`.
4. Put the domain components in `src/components/<domain>/`, with a
   `PageHeader` and an `EmptyState` for the empty case.

## Session and real-time

- The backend sets `access_token` (15 min) and `refresh_token` (7 days) as
  HttpOnly cookies on `login/verify`. The client never sees a token. In
  development Vite proxies `/api` to the backend; in the image nginx does.
- `lib/auth/session.ts` renews the session on demand (any 401) and a minute
  before the access token expires. Renewals are single-flight in the tab and
  serialised across tabs with the Web Locks API, because the backend treats
  a refresh token presented twice as a leak and revokes the whole session.
- `lib/realtime` opens one `EventSource('/api/v1/events')` per tab. Each
  `license.changed` is folded into the Query cache (track detail and the
  lists that hold it), appended to the "Actividad en vivo" feed and shown as
  a toast; `resync` invalidates tracks and licenses. The indicator at the
  bottom of the sidebar shows the connection state.

## Tests

`bun run test` runs the unit tests: the HTTP client (envelope, 401 → one
renewal → retry, opt-out), the session manager (single flight, lock, lost
session, scheduling), timecode parsing and timeline geometry, the error
texts, scope matching, the license actions per state, the cache reducer
for live changes, and the login flow against msw (one tenant skips the
picker, wrong code shows attempts left, a recent code keeps the server's
wait, unknown email).

## Production image

`Dockerfile` builds with `oven/bun:1` and serves `dist/` with
`nginx:1.27-alpine`; `nginx.conf` falls back to `index.html` for client
routes and proxies `/api/` to `http://backend:8080` with buffering off, so
the SSE stream flows. `compose.yml` publishes it on `${FRONTEND_PORT:-5173}`.
